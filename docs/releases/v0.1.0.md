# SmartRoute v0.1.0

SmartRoute v0.1.0 is the first numbered public release of the local-first adaptive routing sidecar for Mihomo and Clash Verge Rev. Its runtime maturity remains experimental: the current integration is intended for informed self-hosting with a tested rollback path, not as a production-ready one-click client.

## Highlights

- Automatic exact-target last-known-good routing: first TCP/TLS-ready path is remembered immediately, reused with one candidate, and overwritten after a successful pre-commit opposite fallback.
- Local HMAC-keyed SQLite persistence with a bounded in-memory startup index and asynchronous writes outside the connection path.
- Availability Guard and independently supervised Engine, plus a macOS user LaunchAgent boundary for top-level restart recovery.
- Idempotent Clash Verge post-script transform that preserves trusted rules and replaces only the final `MATCH` lane.
- Bounded pseudonymous observations, identity-free readiness/route/relay reports, and machine-readable reasons.
- Deterministic Test Lab, pinned Mihomo Lab, full transformed Runtime Lab, latency/load/capacity labs, and checksum-gated active candidate rollback.

## Live evidence used for this release

- Real final-MATCH traffic exercised both Direct and Proxy selection, persisted/reused mappings, and pre-commit fallback.
- The retained automatic index reached 271 exact mappings during the trial: 164 Direct and 107 Proxy at the final release inspection.
- A real terminal-owned Supervisor outage was reproduced and fixed with a user LaunchAgent. A deliberate Supervisor termination then produced a new PID and restored all five local SOCKS topology checks.
- The latest retained observation window contained 585 ready selections: 302 Direct and 283 Proxy. This is descriptive readiness evidence, not a verified application-success or counterfactual-savings claim.

## Upgrade and rollback

The release archive contains the standalone `smartroute` binary, README, and MIT license. Existing live installations must keep their private config, SQLite key/database, candidate backup, and LaunchAgent outside the repository. Replace the binary only while the LaunchAgent is stopped, retain the previous binary, bootstrap again, and require `smartroute doctor -phase running`.

To remove the active transform, restore and reload the original Clash script before stopping the SmartRoute service. Never stop Guard first while the final `MATCH` still targets it.

## Important limits

- TLS readiness means a structurally valid ServerHello, not certificate, HTTP, or application success.
- The declared original fallback is not an executed counterfactual baseline; changed selections and bytes are not proven savings.
- Exact HMAC-keyed automatic mappings are intentionally not suffix-generalized.
- Current local service and Clash integration remain operator-oriented and experimental.
